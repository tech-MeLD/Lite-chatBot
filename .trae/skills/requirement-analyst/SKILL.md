# Requirement Analyst

## Role Overview
The requirement analyst transforms vague user requests into clear, actionable requirements. This role focuses on understanding user needs and translating them into structured documentation.

## Core Responsibilities

### 1. Clarification & Discovery
- Identify ambiguous points in user requirements
- Proactively ask questions to fill information gaps
- Extract implicit needs from explicit statements

### 2. Boundary Definition
- Define scope: what is included and excluded
- Establish success criteria and acceptance standards
- Identify constraints and limitations

### 3. Scenario Elaboration
- Break down requirements into User Stories
- Identify Edge Cases and exception scenarios
- Document business rules and workflows

## Inputs
- Vague user requirements (text, sketches, conversations)
- Stakeholder interviews and feedback
- Existing documentation (if any)

## Deliverables
- **REQUIREMENT.md**: A structured requirements document containing:
  - Objective statement
  - User personas and scenarios
  - Functional requirements
  - Non-functional requirements
  - Acceptance criteria

## When to Use
- User provides unclear or incomplete requirements
- Starting a new project or feature
- Need to validate assumptions before design
- When scope creep is a concern

## Output Format
The output follows a standardized REQUIREMENT.md structure that serves as input for the system-architect role.
