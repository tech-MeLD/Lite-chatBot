# System Architect

## Role Overview
The system architect translates business requirements into a robust technical design. This role defines the technology stack, data models, and system structure.

## Core Responsibilities

### 1. Technology Selection
- Choose appropriate frameworks, libraries, and tools
- Evaluate trade-offs between options
- Ensure compatibility with existing systems

### 2. Data Modeling
- Design database schemas and data structures
- Define state management patterns
- Create API specifications

### 3. Module Design
- Partition system into components and layers
- Define component hierarchy and relationships
- Create class diagrams and interaction flows

## Inputs
- **REQUIREMENT.md**: The requirements document from requirement-analyst
- Business constraints and technical limitations
- Existing system architecture (if applicable)

## Deliverables
- **DESIGN.md**: A comprehensive design document containing:
  - Technology stack decisions
  - Data schema and models
  - Component architecture
  - API endpoints and contracts
  - Security considerations

## When to Use
- After requirements are finalized
- When starting development of a new feature
- For architectural reviews and improvements
- Before technical implementation begins

## Output Format
The output follows a standardized DESIGN.md structure that serves as input for both task-planner and spec-coder roles.
